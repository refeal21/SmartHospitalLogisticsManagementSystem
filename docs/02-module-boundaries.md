# 模块边界

## 总体定位

医院后勤系统位于 BIM 智慧运维平台的业务应用层，依托“数字孪生时空底座”提供空间、设备、资产、环境、人员、事件、工单的统一上下文。系统必须同时支撑日常后勤服务、设施运行保障、环境监管、质量成本管理，并为安全、应急、安保体系提供数据联动。

## 核心用户

- 院领导与后勤管理层：看总体态势、质量、成本、风险、绩效。
- 后勤中心调度员：接单、派单、协调、跟踪、闭环。
- 设备设施运维人员：执行巡检、维修、保养、异常处置。
- 环境与能源管理人员：监测水、电、气、暖、空调、污水、医废、温湿度。
- 服务班组与外包单位：执行保洁、配送、餐饮、被服、维保等任务。
- 安全/应急/安保相关角色：共享告警、事件、空间、人员与处置状态。

## V1 必做业务域

1. 基础运行保障
   - 设备设施台账、空间/BIM 位置、运行状态、告警、巡检、保养、维修。
   - 覆盖强弱电、机房、照明、给排水、暖通空调、医用气体、电梯、食堂基础设施等基础模块。

2. 一站式服务中心
   - 统一报修、服务请求、派单、工单流转、过程记录、满意度、回访、SLA。
   - 服务类型覆盖维修、保洁、配送、被服、餐饮、病区支持、院内导航与空间服务等可扩展场景。

3. 环境监管
   - 数据采集、数据监管、BIM 展示、预警池、报警策略、数据分析。
   - 覆盖室内外环境、智慧卫生间、医疗废物、污水、能源与重点区域环境状态。

4. 综合管理
   - 质量体系、合同管理、考核管理、运营分析、人员管理、运行管理、能耗成本管理、碳排双控。
   - 支持 PDCA：定标准、追过程、看结果、做改进。

## V1 必须打通的数据对象

- 空间：院区、楼栋、楼层、房间、功能区、BIM 构件、空间标签。
- 设备：设备设施、系统分类、位置、运行状态、维保计划、巡检点、告警。
- 事件：告警、报修、服务请求、应急事件、处置记录、升级记录。
- 工单：来源、类型、优先级、SLA、派单、执行、验收、回访、评价。
- 组织：部门、班组、岗位、人员、外包单位、值班计划。
- 管理：合同、质量标准、考核指标、成本、能耗、统计报表。

## 集成边界

- BIM 引擎：提供模型、构件、楼层、空间定位、三维展示和空间选择能力。
- IoT 平台：提供设备遥测、告警、阈值、状态、历史曲线。
- 医院现有系统：HIS、OA、HRP、资产、门禁、视频、安防、能耗、消息平台。
- 第三方维保/外包：通过 API 或导入导出同步工单、人员、合同、绩效。
- AI 能力：用于智能派单、知识库问答、风险预警、趋势分析、报告生成；不直接替代人工审批。

## 暂不作为 V1 主线

- 完整三维 BIM 建模工具。
- 全院真实 IoT 接入和现场协议适配。
- 真实生产级 HIS/HRP/OA 双向集成。
- 安全、应急、安保三大系统的完整重建。
- 移动端原生 App。V1 可先用响应式 Web 或 PWA 思路预留。

## 与安全/应急/安保的关系

后勤系统负责“设施、服务、环境、质量、成本”的运行闭环；安全/应急/安保负责“治理、指挥、现场防控”的风险闭环。两者通过数字孪生时空底座共享空间、人员、设备、事件和工单状态，避免重复建设。
