# PPT 后勤系统功能矩阵

## 提炼范围

本矩阵来自《基于 BIM 的智慧运维平台顶层架构方案》后勤章节第 19-36 页，重点依据第 21 页系统功能架构、第 22-28 页功能逻辑关系、第 29-32 页一二级功能清单、第 33-36 页预期成效与权限治理。本文只沉淀脱敏后的产品结构，不包含 PPT 原图、客户真实数据或公司培训原文。

## 产品定位

智慧后勤管理系统不是展示型大屏，而是面向医院后勤日常运营的功能型管理后台。系统横跨基础运行、后勤服务、环境监管、综合管理四大板块，目标是把设备、空间、人员、物资、工单、质量、合同、成本和运行实绩纳入同一套闭环。

注：第 21 页总览写明“29 个一级功能模块、156 个子项”；第 29-32 页明细页可见数字为 56、43、23、30，合计 152。系统模型同时保留 PPT 总览口径和明细页可见口径，后续补充原始功能清单时再校准差异。

## 业务逻辑关系

| 来源页 | 逻辑关系 | 软件含义 |
|---|---|---|
| 22 | 综合管理下发管理标准，基础运行、后勤服务、环境服务上传实绩 | 综合管理是规则和评价中心，执行域必须沉淀过程数据与结果数据 |
| 22 | 数字孪生时空底座提供技术赋能，外部系统通过集成进入 | 空间、BIM 构件、IoT 点位、外部资产/财务/人事系统都应作为适配边界 |
| 23 | 设施班组管理设备运行，监测预警触发运维处置，并上传维修数据到一站式服务中心 | 设备告警、巡检异常、人工报修都应汇入统一工单调度 |
| 24 | 一站式服务中心联动备件库存、综合维修/巡检等服务管理，生成工作任务和指标实绩 | 工单中心不是孤立模块，必须关联库存领用、班组执行、绩效指标 |
| 25-26 | 环境监管从数据采集进入数据监管、BIM 展示、预警池、报警策略、数据分析，并对接第三方运维 | 环境业务需要“点位-指标-阈值-告警-工单-复盘”的链路 |
| 27 | 质量管理按 PDCA 定标准、追过程、看结果、做改善，并联动合同审核、合同标准、考核验收、结算分析 | 质量和合同必须从过程记录中自动取证，不能只做静态台账 |
| 28 | 电梯管理示例强调多角色协同：领导、管理者、维保、科室等围绕同一设备状态协作 | 专项系统要有角色视图、设备状态、运行异常、维保模式、科室呼叫等协作能力 |

## 建设原则

1. 首页只能作为入口，不能替代业务功能页。
2. 每个核心模块必须能办事：查询、筛选、详情、流转、记录、统计。
3. BIM 不是背景图，而是空间、设备、点位、告警、工单的共同索引。
4. 综合管理不能只做报表，必须从执行过程自动取数，支撑合同、考核和结算。
5. 后续 AI 能力应服务派工、知识推荐、告警聚合、风险预测和运营总结，不替代人工审批。
