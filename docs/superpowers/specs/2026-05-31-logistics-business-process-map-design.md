# 医院后勤 BIM 智慧运维业务流程地图设计

## 背景

当前系统已经有 PPT 功能矩阵、北建院客户数据目录、中科医信竞品功能矩阵，以及工单、资产、物联三个纵切雏形。但前端仍然容易呈现为“模块和卡片堆叠”，原因是资料到业务流程的中间层不够稳定。

本设计用于纠偏：先形成完整业务地图，再按大模块逐个深挖，确保后续数据库、API 和页面都服务真实医院后勤业务闭环。

## 推荐方案

采用“两层推进”：

1. 全局业务地图：一次性铺开医院后勤 BIM 智慧运维的业务域、角色、对象和一级闭环。
2. 模块深挖：按一站式服务、资产巡检、物联告警、BIM 空间、专项后勤、综合管理的顺序逐个做页面契约、领域模型、数据库/API 和前端流程。

不采用“一次性全模块细化”，因为范围过大，会继续失控。不采用“只做工单模块”，因为会丢掉 BIM、资产、物联和质量考核之间的关键关系。

## 业务域

全局地图覆盖以下业务域：

- 运营工作台。
- 一站式服务与工单调度。
- 资产台账与巡检保养。
- BIM 空间运维。
- 物联监测与告警处置。
- 供配电、暖通冷热站、给排水/污水、医用气体、环境质量、医废、电梯等专项系统。
- 仓库耗材、保洁、运送、膳食、被服、太平间等后勤服务。
- 质量、合同、考核、能耗成本和平台治理。

## 核心闭环

系统必须围绕五条一级闭环建设：

1. 服务工单闭环：请求 -> 受理 -> 派工 -> 接单 -> 处置 -> 验收 -> 评价。
2. 资产设施闭环：建档 -> 计划 -> 巡检/保养 -> 异常 -> 工单 -> 履历。
3. 物联告警闭环：采集 -> 阈值 -> 告警 -> 确认 -> 工单 -> 复盘。
4. BIM 空间闭环：空间 -> 设备/点位/工单/告警 -> 现场处置 -> 历史沉淀。
5. 质量合同考核闭环：标准 -> 过程取证 -> 评价 -> 整改 -> 考核/结算。

## 页面契约

每个页面实现前必须明确：

- 页面名称。
- 使用者。
- 业务目标。
- 主对象。
- 入口来源。
- 核心操作。
- 数据区。
- 状态。
- 来源依据。
- 验收流程。

这个契约用于阻止页面只展示资料或指标，保证每个页面都能办事。

## 首批深挖顺序

1. 一站式服务与工单调度。
2. 资产台账与巡检保养。
3. 物联监测与告警处置。
4. BIM 空间运维。
5. 医废、供配电、暖通、给排水、医气、电梯等专项模块。
6. 综合质量、合同、考核、能耗成本。

## 验收标准

- 全局地图必须能覆盖 PPT 四大板块、北建院八类客户系统和竞品二十类功能。
- 每个核心页面必须能追溯到北建院、竞品或 PPT，AI 只能作为工程衔接来源。
- 下一步前端重构必须先从页面契约出发，而不是从卡片布局出发。
- 下一步数据库设计必须从业务对象和状态流转出发，而不是先列 CRUD 表。
