# 医院后勤 BIM 智慧运维全局业务流程地图

## 目标

本文把 PPT、北建院客户调研数据和中科医信竞品功能树转化为“资料到业务流程”的项目级地图。后续数据库、API、前端页面和测试必须从这里继续向下推导，避免重新回到模块堆叠、卡片堆叠或演示壳子。

本文只保存脱敏后的业务流程、对象关系和建设顺序，不保存原始 PPT、Excel、XMind、截图、客户真实点位或内部原文。

## 设计原则

1. 先全局，再深挖：先建立完整业务地图，再按大模块逐个细化。
2. 先闭环，再页面：每个页面必须服务一个真实业务闭环，不能只展示静态指标。
3. 先对象，再数据库：数据库表必须来自业务对象、状态流转和审计要求。
4. 先来源，再 AI：功能细节优先级为客户调研数据、竞品功能树、PPT 架构、AI 工程补齐。
5. BIM 是索引，不是背景：空间、设备、点位、告警、工单、人员和质量记录都要能落到 BIM/空间上下文。

## 一级业务闭环

### 1. 服务工单闭环

触发来源包括人工报修、电话受理、移动报修、巡检异常、物联告警、专项系统报警和管理任务。

流程为：服务请求 -> 受理建单 -> 分类定级 -> SLA 计算 -> 派工建议 -> 调度派单 -> 班组接单 -> 现场处置 -> 挂单/转单/升级 -> 完工提交 -> 验收 -> 回访评价 -> 质量和考核沉淀。

关键约束：
- 工单必须关联来源、空间、设备/点位、班组、SLA、流转记录和评价。
- 所有状态变化必须有操作人、时间、动作、备注和前后状态。
- 前端页面必须同时看到工单池、详情、派工建议、BIM/空间位置、SLA 风险和流转记录。

### 2. 资产设施闭环

流程为：资产建档 -> 空间/BIM 绑定 -> 分类分级 -> 巡检/保养计划 -> 任务生成 -> 执行记录 -> 异常转工单 -> 维修履历 -> 健康度/风险更新。

关键约束：
- 资产不是孤立台账，必须关联空间、系统分类、责任班组、维保单位、巡检计划、维修历史和备件消耗。
- 巡检异常必须能进入统一工单，不另建孤岛流程。
- 资产详情页要能看到生命周期，而不是只显示资产字段。

### 3. 物联告警闭环

流程为：系统/子系统建模 -> 传感器/点位绑定 -> 指标采集 -> 阈值策略 -> 告警生成 -> 告警确认 -> 处置策略 -> 转工单/联动专项 -> 复盘归档。

关键约束：
- 监测点位必须保留客户数据目录中的系统、传感器、位置、可采集字段、希望采集字段、角色和使用端。
- 告警必须能追溯到采集值、阈值、点位、设备、空间和处置工单。
- 强电、暖通、给排水、医气、环境、污水先以适配模型进入，不直接接生产系统。

### 4. BIM 空间闭环

流程为：院区/楼栋/楼层/房间建模 -> BIM 构件/空间映射 -> 设备/点位挂接 -> 工单/告警定位 -> 路径和影响分析 -> 现场处置 -> 空间历史沉淀。

关键约束：
- 空间是业务索引，不只是地图视图。
- 任何工单、告警、资产和巡检任务都应能回到空间上下文。
- V1 可用楼层平面和空间树 mock，不要求完整三维建模工具。

### 5. 质量合同考核闭环

流程为：质量标准/合同要求 -> 服务和巡检过程取证 -> SLA/满意度/异常事件计算 -> 整改任务 -> 复核 -> 考核/结算/运营分析。

关键约束：
- 综合管理不能手工填报为主，必须从工单、巡检、告警、评价和成本记录自动取数。
- 质量问题应能反向追溯到班组、供应商、合同、空间、设备或服务类型。

## 资料到模块的取舍规则

| 决策问题 | 采用规则 |
| --- | --- |
| 客户字段和竞品功能不一致 | 客户字段优先，竞品流程补齐页面和操作颗粒度 |
| PPT 模块很大但暂无客户数据 | 放入全局地图和后续模块，不抢占 V1 深挖顺序 |
| 竞品有成熟页面但 PPT 未强调 | 如果能支撑工单、资产、告警、质量闭环，可纳入 V1 或 V1.5 |
| AI 想补一个功能 | 必须标明是工程衔接、命名、交互或缺口说明，不能作为唯一业务来源 |
| 前端页面很漂亮但无法办事 | 不通过验收，必须回到业务闭环重新设计 |

## 分阶段深挖顺序

### 阶段 0：全局地图与页面契约

目标是把全局业务域、闭环、对象和页面职责定稳。

交付物：
- 全局业务流程地图。
- 页面契约模板。
- 首批核心页面清单。

验收：
- 每个核心页面能说明使用者、业务对象、主流程、关键操作、来源依据和验收方法。

### 阶段 1：一站式服务与工单调度

目标是让后勤系统先能“接事、派事、办事、验事、评价”。

页面顺序：
1. 服务受理。
2. 工单调度。
3. 任务执行。
4. 验收回访。
5. 服务评价。

流程验收：
- 人工报修生成工单。
- 告警和巡检异常进入同一工单池。
- 调度员可按专业、SLA、风险和班组负载派工。
- 班组可接单、挂单、转单、完工。
- 管理者可验收、驳回和查看履历。

### 阶段 2：资产台账与巡检保养

目标是让工单有设备、空间和生命周期上下文。

页面顺序：
1. 资产台账。
2. 资产详情。
3. 巡检计划。
4. 巡检任务。
5. 维修履历。
6. 备件库存联动。

流程验收：
- 资产能绑定空间/BIM、系统分类和责任班组。
- 巡检计划能生成任务。
- 异常能转维修工单。
- 工单结果能回写资产履历和健康状态。

### 阶段 3：物联监测与告警处置

目标是把北建院客户系统和点位字段转成可用的监测/告警/工单模型。

页面顺序：
1. 客户系统目录。
2. 监测点位目录。
3. 指标与阈值策略。
4. 预警池。
5. 告警处置。
6. 趋势和报表。

流程验收：
- 强电、暖通、给排水、医气、环境、污水有统一点位模型。
- 读数进入阈值判定。
- 高风险告警可转工单，并保留来源证据。

### 阶段 4：BIM 空间运维

目标是让空间成为工单、资产、点位和告警的共同入口。

页面顺序：
1. 空间台账。
2. 楼层视图。
3. 设备点位。
4. 告警点位。
5. 工单点位。
6. 空间详情。

流程验收：
- 从空间能进入资产、点位、告警和工单。
- 从工单/告警能反向定位空间。
- V1 使用可替换的空间和构件 mock，为后续真实 BIM 适配器留接口。

### 阶段 5：专项后勤模块

目标是按业务优先级补强专项系统。

优先顺序：
1. 医废管理。
2. 供配电。
3. 暖通冷热站。
4. 给排水/污水站。
5. 医用气体。
6. 电梯。
7. 智慧卫生间/保洁。
8. 仓库耗材/备件。
9. 能耗成本。

验收：
- 每个专项模块必须至少接入“监测/任务/工单/统计/质量”中的三个环节，不能只做独立看板。

## 页面契约模板

后续每个前端页面必须先填写以下契约，再进入实现。

| 字段 | 说明 |
| --- | --- |
| 页面名称 | 页面在菜单和路由中的名称 |
| 使用者 | 主要角色，例如调度员、班组人员、管理者 |
| 业务目标 | 用户进入此页面要完成什么工作 |
| 主对象 | 页面围绕哪个对象工作，例如工单、资产、告警 |
| 入口来源 | 从工作台、消息、BIM、资产详情或其他页面进入 |
| 核心操作 | 用户可执行的状态变化、提交、审批、派发或处置动作 |
| 数据区 | 列表、筛选、详情、时间线、指标、图表、附件等 |
| 状态 | 空、加载、异常、无权限、成功、失败、冲突 |
| 来源依据 | 北建院、竞品、PPT 或 AI 衔接说明 |
| 验收流程 | 至少一条能端到端跑通的用户流程 |

## 下一步执行约束

1. 不再新增独立展示卡片式页面，先为每个页面补页面契约。
2. 下一轮优先深挖“一站式服务与工单调度”，把服务受理、工单调度、任务执行、验收回访连成前端流程。
