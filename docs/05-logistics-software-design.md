# 医院后勤功能型后台设计

## 设计纠偏

上一版页面偏向“PPT 架构驾驶舱”，能表达四大板块，但不能支撑真实后勤人员办事。本设计把系统改为功能型管理后台：驾驶舱只是入口，核心是菜单、列表、筛选、详情、派工、执行、验收、统计和审计。

## 目标用户与核心工作

| 用户 | 高频工作 | 系统必须提供 |
|---|---|---|
| 后勤调度员 | 受理报修、派工、催办、升级、回访 | 工单池、派工面板、SLA 倒计时、班组负载、处置记录 |
| 设施运维人员 | 巡检、维修、保养、异常反馈 | 任务清单、设备详情、BIM 定位、备件领用、维修记录 |
| 环境监管人员 | 盯点位、看预警、处置医废/污水/卫生间异常 | 点位列表、预警池、报警策略、处置工单、趋势分析 |
| 后勤管理层 | 看质量、成本、合同、外包绩效 | 运营分析、质量考核、合同履约、成本能耗、人员实绩 |
| 外包/服务班组 | 接任务、反馈结果、提交证据 | 班组任务、执行记录、附件证据、评价结果 |

## 菜单结构

| 一级菜单 | 二级页面 | 页面类型 |
|---|---|---|
| 运营工作台 | 后勤首页、待办中心、风险告警 | 指标、待办、告警、趋势 |
| 一站式服务 | 服务受理、工单调度、任务执行、验收回访、服务评价 | 表单、列表、流程、评价 |
| 设备设施 | 设备台账、巡检保养、维修记录、备件库存、电梯专项、暖通/给排水/医气专项 | 台账、详情、计划、库存、专项 |
| BIM 空间 | 空间台账、楼层视图、设备点位、告警点位、工单点位 | 空间树、平面/BIM、点位联动 |
| 环境监管 | 环境点位、预警池、报警策略、医废处置、智慧卫生间 | 点位、规则、告警、处置 |
| 综合管理 | 质量标准、合同管理、考核管理、人员班组、运营分析、能耗成本、碳排双控 | 标准、台账、考核、报表 |
| 系统治理 | 角色权限、流程配置、SLA 配置、字典配置、审计日志 | 配置、权限、审计 |

## 首屏页面设计

首屏不是宣传页，也不是大屏，而是后勤管理后台首页。布局参考用户提供的蓝白企业后台截图：

- 左侧深蓝导航栏：LOGO、一级菜单、当前选中项。
- 顶部浅色工具条：院区、日期、搜索、消息、用户。
- 上方 KPI：今日工单、超时风险、运行告警、设备完好率、SLA 达成率。
- 中部主区域：工单调度表格、BIM 空间业务定位、环境预警池。
- 右侧辅助栏：班组负载、重点风险、质量/合同提醒。
- 下方分析区：服务趋势、告警趋势、能耗成本、满意度。

## 核心业务闭环

### 服务闭环

服务请求 -> 受理登记 -> 工单池 -> 派工 -> 执行反馈 -> 验收 -> 回访评价 -> 考核归档。

关键页面：
- 服务受理：登记来源、服务类型、空间、设备、优先级、联系人。
- 工单调度：按 SLA、优先级、区域、班组负载派单。
- 任务执行：查看任务、提交过程、领用备件、上传证据。
- 验收回访：确认结果、满意度、二次派工、投诉。

### 设施运行闭环

设备台账 -> IoT/巡检/人工发现异常 -> 告警或报修 -> 工单 -> 维修/保养 -> 复盘 -> 生命周期记录。

关键页面：
- 设备台账：设备、系统、空间、BIM 构件、状态、维保单位。
- 巡检保养：计划、路线、点位、异常、转工单。
- 维修记录：故障原因、处置过程、备件、停机影响。
- 备件库存：库存、安全库存、工单领用、采购需求。

### 环境监管闭环

点位采集 -> 阈值策略 -> 预警池 -> 确认告警 -> 处置工单 -> 数据分析 -> 策略优化。

关键页面：
- 环境点位：CO2、温湿度、负压、污水、医废、卫生间等。
- 预警池：级别、位置、持续时间、影响范围、确认状态。
- 报警策略：指标、阈值、规则、联动对象。
- 医废处置：暂存间、负压、转运、称重、交接、合规记录。

### 质量成本闭环

质量标准/合同标准 -> 过程采集 -> 结果评价 -> 问题整改 -> 考核结算 -> 运营分析。

关键页面：
- 质量标准：检查项、评分规则、适用服务。
- 合同管理：合同台账、履约节点、服务范围、结算状态。
- 考核管理：满意度、投诉、不合格事件、整改复核。
- 运营分析：SLA、成本、能耗、人员效率、外包绩效。

## 前端页面组件

| 组件 | 用途 |
|---|---|
| AppShell | 左侧菜单、顶部栏、内容区骨架 |
| MetricStrip | 首页 KPI 指标 |
| DispatchTable | 工单调度表格，支持状态、优先级、SLA 展示 |
| SpatialOperationsMap | BIM/空间业务定位示意，展示设备、告警、工单点位 |
| AlertPool | 环境和设备告警池 |
| TeamLoadPanel | 班组负载与派工建议 |
| ModuleNavigator | 从 PPT 功能矩阵生成模块入口 |
| TrendPanel | 服务、告警、能耗、满意度趋势 |

## 后端 API 方向

| API | 用途 |
|---|---|
| `GET /api/logistics/blueprint` | 返回菜单、模块矩阵、首屏数据和核心工作流 |
| `GET /api/operations/dashboard` | 保留兼容，返回运营摘要 |
| `GET /api/operations/work-orders/active` | 返回待处理工单 |
| `GET /api/operations/assets/risk` | 返回风险设备 |

## V1 验收标准

- 页面结构必须体现功能型软件，而不是 PPT 展示页。
- 左侧菜单不得只停留在四大板块，必须展开到一站式服务、设备设施、环境监管、综合管理等办事入口。
- 首屏必须包含可操作业务对象：工单、告警、设备、空间、班组、合同/质量提醒。
- 后端必须提供结构化功能矩阵和工作台数据，前端不能只硬编码 PPT 文案。
- 自动测试必须覆盖：菜单结构、PPT 功能矩阵、核心工单排序、移动端无横向溢出。
