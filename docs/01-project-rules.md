# 项目级规则

## 第一性原理

本项目的目标是从 0 到 1 开发一个强大的医院后勤管理系统，而不是制作演示壳子。所有工作都必须服务于真实医院后勤运营：可落地、可扩展、可审计、可集成、可持续运维。

## 资料与安全边界

- PPT、公司培训文件、客户信息、项目现场信息只作为本地参考资料，不进入 public GitHub 仓库。
- 严禁提交或粘贴认证凭证、API Key、数据库密码、Token、SSL 证书、生产服务器信息、内网拓扑、客户真实业务数据。
- 后续 GitHub 只上传生成的系统代码、工程配置、测试、脱敏后的项目文档。
- 示例数据必须是 mock 数据，不能使用客户真实数据。
- `.env`、图片、PPT、培训原文、导出截图必须保持在 `.gitignore` 内。

## AI 辅助开发规则

- 先约束，再生成：任何 AI 进入项目必须读取 `AGENTS.md` 和 `docs/` 下的项目规则。
- 先设计，再编码：涉及模块、数据库、权限、安全、集成的改动必须先有文档或任务说明。
- 小步快跑：一个功能点对应一次可验证的改动和一次提交。
- 信任但验证：AI 产出的代码、文档、架构都必须通过运行、测试、审查或人工业务判断确认。
- 复杂问题采用结构化 DEBUG：问题描述、环境信息、复现步骤、期望行为、实际行为、已有线索、相关代码、验证结论。

## 工程质量底线

- 后端必须有清晰的领域层、应用层、接口层、基础设施层边界。
- 前端必须是可用的业务系统界面，优先支持高频工作流、列表筛选、详情追踪、状态流转和异常处理。
- 数据模型必须保留审计字段、状态字段、空间/BIM 关联字段、组织/角色字段。
- 所有外部系统接入必须走适配器：BIM、IoT、HIS/OA/HRP、资产、安防、能耗、第三方维保。
- 安全功能必须覆盖认证、授权、最小权限、输入校验、输出编码、操作审计、敏感信息脱敏。
- 测试至少覆盖领域逻辑、API 合约、权限边界、核心页面流程和异常路径。

## GitHub MCP 配置状态

已在用户级 Codex 配置中加入 GitHub 官方远程 MCP：

```toml
[mcp_servers.github]
url = "https://api.githubcopilot.com/mcp/"
bearer_token_env_var = "GITHUB_PAT_TOKEN"
```

当前仍需要在用户环境变量中设置 `GITHUB_PAT_TOKEN`，并重启 Codex 后验证 MCP 可见。Token 不得写入本仓库。
